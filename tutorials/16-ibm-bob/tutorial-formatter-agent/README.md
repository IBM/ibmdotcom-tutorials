# tutorial-formatter-agent

A CLI agent that reformats IBM Bob tutorial Markdown files into the
[bob.ibm.com](https://bob.ibm.com) MDX publication style, using the
universal [`TUTORIAL_TEMPLATE.mdx`](../TUTORIAL_TEMPLATE.mdx) as its style
guide and **IBM watsonx.ai** as its LLM backend.

---

## What it does

| Step | Description |
|---|---|
| **1** | Reads the raw tutorial `.md` file you provide |
| **2** | Loads `TUTORIAL_TEMPLATE.mdx` as the structural and style reference |
| **3** | Loads keywords from `keywords.txt` (auto-detected) or `--keywords <path>` override |
| **4** | Calls the watsonx.ai chat API with a structured system prompt derived from the template's style rules |
| **5** | Streams the formatted `.mdx` back, showing a live character count |
| **6** | Asks you to confirm the output path, then writes the file |

The template is created **once** and reused across every tutorial. The agent
applies it consistently on every run.

## Setup

```bash
# 1. Install dependencies
cd tutorial-formatter-agent
npm install

# 2. Create your .env file
cp .env.example .env
# Edit .env — set WATSONX_API_KEY and WATSONX_PROJECT_ID

# 3. Build the TypeScript source
npm run build
```

## Get your watsonx.ai credentials

You need two values from IBM Cloud:

### `WATSONX_API_KEY`

1. Go to [IBM Cloud → Manage → IAM → API keys](https://cloud.ibm.com/iam/apikeys)
2. Click **Create an IBM Cloud API key**
3. Copy the key — it is shown only once

### `WATSONX_PROJECT_ID`

1. Open [watsonx.ai](https://dataplatform.cloud.ibm.com/wx/home)
2. Open your project → **Manage** tab → **General**
3. Copy the **Project ID** shown under the project name

## Usage

### Interactive mode (recommended for first-time use)

```bash
node build/index.js
```

The agent prompts you for:
- Path to the raw Markdown tutorial
- Path to `TUTORIAL_TEMPLATE.mdx` (auto-detected if it is in the parent directory)

Keywords are loaded automatically — no prompt needed (see below).

### Keywords file

Place a `keywords.txt` file in the workspace root. The agent finds it
automatically; no flag required. You can use plain lines, a numbered list,
or bullets — all formats are accepted and can be mixed:

```text
# keywords.txt — any of these formats work

# plain
watsonx.ai
IBM Granite

# numbered list (paste directly from a doc)
1. retrieval-augmented generation
2. tool calling
3. agentic AI

# bullets
- Granite 3.3
* function calling
```

Blank lines and lines starting with `#` are ignored. List prefixes (`1.`, `2)`,
`-`, `*`) are stripped automatically, so you can paste a numbered list from any
document without editing it first.

To use a different file, pass `--keywords`:

```bash
node build/index.js path/to/my-tutorial.md --keywords path/to/other-keywords.txt
```

If no `keywords.txt` is found and no `--keywords` flag is given, the agent runs
without keywords.

### With all arguments

```bash
node build/index.js path/to/my-tutorial.md \
  --template path/to/TUTORIAL_TEMPLATE.mdx \
  --keywords path/to/keywords.txt
```

### Development mode (no build step required)

```bash
npm run dev path/to/my-tutorial.md --keywords path/to/keywords.txt
```

Uses [`tsx`](https://github.com/privatenumber/tsx) to run TypeScript directly.

## Project structure

```
tutorial-formatter-agent/
├── src/
│   ├── agent.ts        # Core agent — prompt construction + watsonx.ai streaming
│   └── index.ts        # CLI entry point — interactive prompts + file I/O
├── build/              # Compiled output (generated by `npm run build`)
├── .env.example        # Environment variable template
├── package.json
├── tsconfig.json
└── README.md
```

### `src/agent.ts`

The stateless formatting engine. Accepts:
- `inputPath` — raw Markdown tutorial
- `templatePath` — `TUTORIAL_TEMPLATE.mdx`
- `keywords` — terms to weave into the output
- `apiKey` / `projectId` / `serviceUrl` / `model` — watsonx.ai configuration

Calls `watsonxClient.textChatStream()` with `system` + `user` messages and
streams the response. Returns the formatted MDX string and a suggested output
file path. Supports an `onChunk` callback for live progress display.

### `src/index.ts`

The interactive CLI shell. Handles:
- Argument parsing (`positional[0]` = input file, `--template` flag, `--keywords` flag)
- Validation of `WATSONX_API_KEY` and `WATSONX_PROJECT_ID` with clear error messages
- Auto-detection of `TUTORIAL_TEMPLATE.mdx` and `keywords.txt` by walking up the directory tree
- Keyword loading from auto-detected `keywords.txt` or explicit `--keywords` path (no interactive prompt)
- Spinner with live character count during streaming
- Output path confirmation before writing

## How the template is used

The agent reads [`TUTORIAL_TEMPLATE.mdx`](../TUTORIAL_TEMPLATE.mdx) at runtime
and extracts the **STYLE RULES** comment block to build the LLM system prompt.
This means:

- Updating the template automatically updates the agent's formatting rules —
  no code changes required.
- The template is the single source of truth for all style decisions.

## Adding a new tutorial

1. Write the raw tutorial in Markdown (any structure).
2. Add any terms to preserve to `keywords.txt` in the workspace root.
3. Run the agent:
   ```bash
   node build/index.js path/to/new-tutorial.md
   ```
4. Review the generated `.mdx` file and make any manual adjustments.

## Extending the agent

### Use a different model

Set `WATSONX_MODEL` in your `.env` to any model ID available in your
watsonx.ai instance. All models use the same `textChatStream` interface —
no code changes needed.

### Use a different region

Set `WATSONX_URL` in your `.env` to the endpoint for your provisioned region
(Frankfurt, Tokyo, London, etc.).

### Add output validation

After the stream loop in `agent.ts`, parse the MDX output with a
Markdown/MDX parser (e.g., `remark` + `remark-mdx`) to validate the structure
before returning it.

### Batch processing

Wrap `formatTutorial` in a loop over a directory of `.md` files to format
multiple tutorials in one run.
